# 기술 설명 — 어떻게 고쳤나

삼국지6를 macOS에서 돌릴 때 부딪히는 두 가지 큰 문제(**한글 깨짐**, **전투 중 프리징**)의 원인과 해결법을 정리합니다.

---

## 1. 한글 깨짐

### 증상
- 대부분의 한글은 나오는데, **일부 UI(특히 상단 툴바의 군주 이름)** 가 `□□□`(세로 막대)로 깨짐.
- 처음엔 메뉴바·대화상자 전체가 깨지기도 함.

### 원인 (두 겹)
1. **Wine 기본 폰트에 한글이 없음** — Wine은 대화상자/메뉴에 `MS Shell Dlg`, `MS Sans Serif`, `System` 같은 폰트를 쓰는데, 기본 제공 폰트에는 한글 글리프가 없습니다.
2. **`System` 폰트의 charset 함정** — 게임은 군주 이름 툴바를 `CreateFont(facename="System", charset=HANGEUL_CHARSET)` 로 그립니다. Wine에는 `hvgasys.fon` 이라는 서구권 비트맵 폰트가 `"System"` 패밀리 + `charset=129(한글)` 로 등록돼 있어서, 이 요청에 **정확히 매칭**되어 최우선 선택됩니다. 이 폰트엔 한글이 없어 `.notdef`(막대)로 렌더링됩니다. 이 정확 매칭이 먼저 잡히기 때문에, 아무리 폰트 대체(FontSubstitutes)를 걸어도 **무시**됩니다.
   - 보조 원인: macOS `AppleGothic.ttf` 에는 `OS/2` 테이블이 없어 Wine이 이 폰트를 명시적 `HANGEUL_CHARSET` 폰트로 분류하지 못합니다. 그래서 `charset=DEFAULT` 요청은 AppleGothic으로 잘 가도, 명시적 `charset=129` 요청은 안 갑니다.

### 해결
1. **AppleGothic 설치** — macOS 시스템의 `AppleGothic.ttf` 를 Wine prefix의 `drive_c/windows/Fonts/` 로 복사.
2. **폰트 매핑(FontSubstitutes/Replacements)** — `MS Shell Dlg`, `MS Sans Serif`, `System`, `굴림`, `바탕`, `돋움` 등을 전부 `AppleGothic` 으로 매핑.
3. **메뉴바 폰트(WindowMetrics)** — 상단 Win32 메뉴바는 별도 폰트(NonClientMetrics)를 쓰므로, `MenuFont`/`CaptionFont`/`MessageFont` 등을 AppleGothic·HANGEUL_CHARSET LOGFONT 로 직접 설정.
4. **핵심 — `hvgasys.fon` 제거** — 위 대체가 안 먹히던 `System`+charset129 툴바를 고치려면, Wine의 `share/wine/fonts/hvgasys.fon` 을 치워야 합니다(이름 변경). 그러면 정확 매칭 대상이 사라져 → `"System"="AppleGothic"` 대체가 발동 → 한글이 정상 렌더링됩니다.

이 설정들은 `assets/reg/` 의 5개 레지스트리 파일과, Wine 빌드에서 `hvgasys.fon` 을 제거한 것(`wine.tar`)에 반영돼 있습니다.

## 2. 전투 중 프리징

### 증상
- 지도/커맨드 화면은 멀쩡한데, **전투(실시간 애니메이션)를 진행하면 게임 전체가 멈춤**(작업표시줄 시계까지 정지).

### 원인
이 문제는 **가상머신(UTM/QEMU 등)에서 돌릴 때** 발생합니다.
- 20년 된 32비트 DirectDraw 게임 → Windows의 x86→ARM 번역(Prism) → **ARM64 하이퍼바이저(HVF)** 로 이어지는 이중 에뮬레이션 스택에서, **타이머·인터럽트 신호가 게스트에 전달되지 못하는** 순간 전체가 멈춥니다.
- 실시간 애니메이션/이벤트가 그 순간을 잘 유발합니다. 신호가 끊긴 시점이 CPU가 쉬는 중이면 CPU 0%로, 연산 중이면 CPU 99%로 멈추지만 **뿌리는 하나**입니다.
- 즉 이건 게임/Windows 버그가 아니라 **가상화 계층의 태생적 한계**라, VM 안에서 아무리 튜닝해도(코어 수 조절, GPU 가속 끄기 등) 완전 제거가 안 됩니다.

### 해결 — VM 대신 Wine
**Wine은 가상머신이 아닙니다.** Win32 API 호출을 macOS로 직접 번역하고, x86→ARM 변환은 Rosetta가 CPU 레벨에서(올바른 메모리 순서로) 처리합니다. **하이퍼바이저·vCPU·타이머 주입 계층이 아예 없으므로**, 이 프리징이 구조적으로 발생할 수 없습니다.

그래서 이 도구는 게임을 **Wine으로** 실행합니다.

---

## 3. 실행 환경 구성 요약

- **Wine**: WineHQ Stable, `hvgasys.fon` 제거(폰트픽스).
- **prefix**(`~/.wine-sam6`): 설치 시 `wineboot` 로 새로 생성 → `assets/reg/` 주입 + AppleGothic 복사.
  - 가상데스크톱 1280x960 (게임이 640x480이라 2배로), 한글 폰트 매핑, 메뉴 폰트 등.
- **런처**: `LANG=ko_KR.UTF-8`(코드페이지 949) 로 실행해야 한글이 CP949로 올바로 디코드됨. 게임 폴더에서 `wine SAM6.EXE`.
- **게임 파일**: 사용자 소유(이 도구에 미포함).

> 참고: 게임 에디터(San6edit)는 Wine의 새 WOW64 SEH 한계로 한글 상태에서 크래시하므로, 에디터가 필요하면 별도의 Windows 환경(VM 등)이 필요합니다. 게임 본체는 위 방법으로 잘 돌아갑니다.
